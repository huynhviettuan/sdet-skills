# Knowledge-Base Structure

The folder the skill produces, what each page holds, and the templates. Pages are Markdown with Mermaid diagrams so
they render on GitHub, GitLab, VS Code and most wikis, and plain text so `grep` finds everything.

## Folder

```text
<project>-kb/
  README.md                  start here: what it is, reading paths per audience, page map, freshness, coverage
  overview.md                product, problem, goals, users, scope in/out, status and milestones, key numbers
  glossary.md                terms, acronyms, synonyms and translations, with where each is defined
  actors-and-permissions.md  roles, responsibilities, the permission matrix, approvals
  domain-model.md            entities, key attributes, relationships (ER diagram), lifecycles (state diagrams)
  flows/README.md            the flow catalogue: one row per flow with trigger, actors, outcome, sources
  flows/<nn>-<flow>.md       one page per business flow
  business-rules.md          rules by area, with the documents' own IDs
  requirements.md            functional requirements by module, non-functional requirements, acceptance criteria
  integrations.md            external systems, APIs, imports/exports, notifications, devices
  decisions.md               decisions and assumptions with dates, superseded ones, still-open choices
  analysis.md                conflicts, gaps, ambiguities, duplicates, stale content, missing documents, risks; OQ list
  testing-view.md            risk areas, testable rules and limits, flows to cover, suggested techniques
  index.md                   A–Z topic index and "where do I find…" questions → page#anchor
  changelog.md               each run: date, sources new/changed/removed, pages updated
  _sources/                  generated by ingest.py: manifest.json, inventory.md, text/ (do not edit)
  _digests/<id>-<slug>.md    one card per source (map step)
```

Pages with nothing to say for this project are omitted, not left empty; the README lists what exists. A very large
project may split a page (`business-rules/<area>.md`) — keep the top-level file as the index for that split.

## Citations

`[S07 L120]` — source id from the manifest and the line in its extracted text (`_sources/text/S07-….md`).
Ranges `[S07 L120-L140]`; several `[S07 L120; S19 L88]`; an image `[S41]` (no line). The README explains the format
and links the inventory, so any citation is two clicks from the original wording.

Cite at the level of the claim: one citation per bullet, table row or sentence that states a fact. A summary
paragraph cites the sources it summarizes. Inferences are written *(inferred from [S03 L40], [S06 L12])*.

## Digest card

`_digests/S07-business-rules.md` — written while reading the source, section by section:

```md
# S07 — Business rules

Three to five lines: what the document is for and what it decides.
```

Cards are working notes: concise, complete on facts, no prose. The pages are built from them.

## Page templates

**README.md**

```md
# <Project> — knowledge base

<One paragraph: what the product is, for whom, and the state it is in.> [citations]

Built on <date> from <n> documents (<words> words) in `<sources>`; <m> findings in [analysis](analysis.md).

## Start here
| If you are… | Read, in order |
|---|---|
| new to the project | overview → glossary → flows → domain model |
| testing it | testing view → flows → business rules → analysis |
| building it | overview → domain model → requirements → integrations → decisions |
| deciding things | analysis (open questions) → decisions |

## Pages
| Page | What's in it |
|---|---|

## Coverage
<n> of <n> sources digested; <images> images described; <ocr> need OCR (listed in analysis).
Citations `[S07 L120]` point to `_sources/text/` — see the [inventory](_sources/inventory.md).
```

**flows/<nn>-<flow>.md** — see `flows-and-models.md` for the full template.

**business-rules.md** — one table per area:

```md
## Contracts
| ID | Rule | Applies to | Source |
|---|---|---|---|
| BR-210 | A contract can be edited only before approval | Contract | [S07 L88] |
```

**glossary.md** — `| Term | Meaning | Also called | Defined in |`, alphabetical; the source-language term first
when the product's UI uses it (Vietnamese UI label, English concept).

**analysis.md** — see `analysis.md`.

**index.md** — alphabetical topic → links (`Burn Show → [flows/05-sessions.md#burn-show], [business-rules.md#sessions]`),
then a "Where do I find…" table of the questions people actually ask ("How is PT revenue split?").

## Writing style

- Short sentences, present tense, the product's own terms; explain a term the first time it appears on a page and
  link the glossary.
- Tables for anything with more than three comparable items; diagrams for flows and lifecycles.
- Numbers exactly as the sources state them (with unit and source); never round or convert silently.
- One idea per heading so anchors in the index stay meaningful.
