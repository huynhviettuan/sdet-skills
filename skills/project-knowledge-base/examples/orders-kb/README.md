# Example: the Orders knowledge base

A complete, checked run of the `project-knowledge-base` skill on four small, deliberately messy documents. It
shows what the skill produces (`kb/`), how every statement cites a source line, how a contradiction between two
documents surfaces as a conflict instead of being resolved silently, and how `test-case-design` reads the result.

The domain is the same Orders service as `skills/security-testing/examples/vuln-api/` (tenants `tenant-a` and
`tenant-b`; roles customer, manager, admin; orders with a note of at most 200 characters and the statuses
`new`, `paid`, `shipped`, `cancelled`). Everything is synthetic; the example users and the example password in the
roles sheet are documented there as examples.

## Layout

| Path | What it is |
|---|---|
| `sources/` | the four input documents, read-only: a PRD draft with an open TODO, meeting notes whose decision D-01 contradicts the PRD's cancellation rule, a customer FAQ with stale numbers, a one-page roles sheet |
| `kb/_sources/` | generated by `ingest.py`: `manifest.json`, `inventory.md`, `text/S01…S04` (the lines citations point at) |
| `kb/_digests/` | one card per source, written while reading it |
| `kb/*.md`, `kb/flows/` | the pages per `references/kb-structure.md` |
| `parse-probe-cases.md` | two test cases that exist only so `check_cases.py --kb` has something to parse (one specified case with a checked evidence quote, one assumption case naming the conflict) |

What to look at first: `kb/analysis.md` C-1 (the PRD's "cancel until shipped" against the sync's "24 hours after
payment"), `kb/domain-model.md` (the lifecycle with both disputed edges labelled), and `kb/testing-view.md` (the
"Testable rules" and "Not testable yet" tables).

## Verify

From the repo root:

```bash
python skills/project-knowledge-base/scripts/ingest.py skills/project-knowledge-base/examples/orders-kb/sources skills/project-knowledge-base/examples/orders-kb/kb
python skills/project-knowledge-base/scripts/check_kb.py skills/project-knowledge-base/examples/orders-kb/kb
python skills/test-case-design/scripts/check_cases.py skills/project-knowledge-base/examples/orders-kb/parse-probe-cases.md --kb skills/project-knowledge-base/examples/orders-kb/kb
```

Re-running `ingest.py` rewrites `kb/_sources/` (ids are stable; `manifest.json` records the absolute sources path
and the run time, so it differs per machine) and must report every source as `unchanged`.

Results on 2026-11-03; `check_kb.py` and the `--kb` run are re-earned on every push by CI's `Skill examples` job
(`scripts/check-examples.sh`), the links by `node scripts/check-repo.mjs`:

```text
ingest.py:      4 files | status {'ok': 4} | change {'new': 4, 'changed': 0, 'unchanged': 0, 'removed': 0}
                words extracted: 1792
check_kb.py:    20 pages | 4 readable sources | 4 digests | 4 sources cited in pages
                0 error(s), 0 warning(s)
check_cases.py: 2 cases in 1 file(s) | 3/22 requirement IDs named by a case | catalogue from 4 knowledge-base sources
                testable rules (testing-view.md): 1 of 14 with a case
                not testable yet (testing-view.md): 5 rules wait for an answer
                0 error(s), 1 advisory note(s)
```

`kb/analysis.md` was written by the coordinating session from the content the building agent returned: a tool
policy refused that agent's write of the file, and it stopped rather than write it another way (repository rule 1).
`check_kb.py` verifies that every cited line exists, not that a quote is on it; three quotes were spot-checked
against `_sources/text/` when the page was placed (C-1 both sides, C-2's matrix row).
