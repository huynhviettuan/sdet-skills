| D-01 | 2026-10-28 | Three supported stacks (Playwright/TS, Selenium+RestAssured/Java, pytest+Playwright/Python); C#, Cypress, WebdriverIO, Appium are *planned* | The stack contract makes adding one mechanical; three prove the composition design | Adding a stack without meeting every line of the contract |

| D-03 | 2026-10-28 | A knowledge base raises `KQ-` questions; the sources' own `OQ-` IDs are reused verbatim when they already ask it | Two `OQ-012`s meaning different things are worse than none | Inventing an OQ for a question a source already numbers |
| D-04 | 2026-10-28 | Conflicts in a KB's analysis are graded High/Medium/Low; `check_cases.py --kb` refuses `Basis: specified` only for High and Medium | Low is wording/cosmetic by definition; blocking on it would make every case an assumption | Treating a Low conflict as a blocker |
| D-05 | 2026-10-28 | `can-fail.mjs` mutates literals only (strings, numbers), skips assertion messages, flags polling helpers | A mutated expression often fails to compile, and a compile error would count as a false "killed" | Operator or expression mutation (candidate: swap `toBe`/`not.toBe`, which always compiles) |
| D-06 | 2026-10-28 | Heuristic checks (vague, status-only, personal data) are advisory until measured on a held-out set; the status-only rule is judged per case, not per line | Per line it flagged 10 % of a real catalogue, mostly falsely | Failing a run on a lexical hint |
| D-07 | 2026-10-28 | The two `document-package.md` references (product docs vs automation docs) stay separate | Different audiences, folder trees and quality questions; merging saves lines and costs clarity | A single "documentation package" reference |
| D-08 | 2026-10-28 | Evals run on demand (manual workflow, local command), never on push | A real model per run costs money and needs credentials; self-tests cover what can be deterministic | Blocking CI on an eval score |
| D-09 | 2026-10-28 | Example suites run nightly against the public demo apps, not on every push | They take 6 minutes per stack and depend on third-party hosts | Making the README's "verified" claim without the nightly job |
| D-10 | 2026-10-28 | `OQ-13` (a Gym CRM business question) stays human-only; the pipeline never answers a clarification | The user's call during the pilot; an answer becomes a trusted source and must come from its owner | Any skill answering a product owner's question |
| D-11 | 2026-10-28 | The Manual QA Agent repo's docs are fixed when our sync finds them wrong, but committed by the user | It is a separate repo with its own history; we edit what we verified against code | Pushing or committing there from this repo's sessions unasked |
| D-12 | 2026-11-01 | A denied tool call stops the step; a subagent that routed around a refusal produced a defective run even when its output was correct | Happened once (analysis page copied through the shell); the output was re-verified by hand | Treating a workaround as acceptable because the result checked out |
| D-13 | 2026-11-01 | Teardown success means the record is gone (verified by a GET), never that the delete returned 200; a non-200/404 delete gets one GET-checked retry, then counts as a leak | The nightly run of 2026-10-30 failed on a Petstore `DELETE` answering 304 while the pet was in fact deleted; the Java factory had the opposite flaw and never noticed a leak | Judging cleanup by a status code in either direction |
| D-14 | 2026-11-02 | The pipeline runs as a team: a coordinator owns the status and spawns one isolated subagent per stage; stages 3 and 4 fan out over disjoint write paths; shared files are merged by the coordinator from returned registration lines; the reviewer never sees the writers' conversations | One context across seven stages degrades by stage 4 and costs more; parallel builders had already worked in this repo when their paths were disjoint | Sharing a conversation between stages; two agents writing one fixture or registry file; a reviewer that saw the writing |
| D-15 | 2026-11-02 | Four stop rules are hooks, not prose: no merge/push to the default branch, no production host, no fixed sleep, no edit to an existing assertion in a test; the audit runs after every write. A blocked call is a stop to report | A rule a model can break under pressure will be broken under pressure; the hooks make rule 2 of CLAUDE.md a gate. `ALLOW_ASSERTION_EDIT=1` is a person's override | Retrying a blocked call another way; a scaffold without `guard-hooks.mjs` |
| D-16 | 2026-11-02 | `automation-status.json` with a schema is the source of truth; the Markdown status is rendered from it and never edited | The coordinator and headless runs need a shape they can validate; people need prose; two hand-maintained copies drift | Editing the `.md`; a stage agent writing either file |
| D-17 | 2026-11-02 | Model per stage: Opus for assess/design, Sonnet for build/implement/verify/review, Haiku for triage | Judgement-heavy and rare steps get the strongest model; repetitive classification the cheapest | One model for every stage |
| D-18 | 2026-11-02 | On a shared server a case asserts the contract on the records the test owns; a whole-body schema check over strangers' records is a separate case for a server you control | The public Petstore served three spec-violating pets planted by others; failing our contract tests on their data tests the server's input validation, not our API usage. The test was not loosened: the case was restated first, the tests followed | Loosening the assertion in the test; keeping a permanently red case against a server nobody owns |
| D-19 | 2026-11-02 | Agents that run tests or `can-fail` never share a working tree; the reviewer works from a detached worktree of HEAD | `can-fail` rewrites test files while it runs; in the pilot the reviewer's first run saw a `__mutant__` literal written by the verify agent and reported a false red; its worktree run was correct | Running verify and review on one tree; any parallel test run on a tree another agent is mutating |
